Borrowed Organization combat-value arithmetic: 5788B0 / 57DC40
============================================================

Scope
  crates/aa-combat/src/organization_combat_value.rs exposes mandatory mutable
  read/output services over a caller-owned Organization. recompute never builds
  a projected Organization and never delays stores until successful completion.
  This is the arithmetic leaf, not a complete saved-map or gameplay milestone.
  The saved runtime binding and its actual-world evidence belong to the separate
  saved-org-combat work; this folder makes no natural-map success claim.

Native instruction order
  5788B3 reads signed count before 5788BB resets current+68 and 5788C2 resets
  maximum+6C. The initial count controls the first iteration even if state changes
  during the resets. 5788CB captures the +28 member-array pointer.
  A present member's +74 Performer supplies 57DC40: Performer+4 owner -> owner's
  +60 Body -> health+10 / maximum+14 (or exactly1 for absent Body), then multiply
  Performer+60. This ratio/product remains x87 extended until current is stored.
  5788E5 adds current+68; 5788E8 recaptures the array pointer BEFORE 5788EB stores
  current+68. 5788EE rereads the member from that captured array, 5788F1 rereads
  its Performer, and 5788F4 reads only Performer+60; it does not reread Body.
  Vacancy resolves layout+18/+28 index through current parameters+1C. Only
  flags+174 bit5 permits a +1E4 read. Each maximum add stores to binary32 at
  578923. Count is reread at 578926 before increment/comparison. Array identity
  is retained across vacant/no-Performer branches, as the instructions require.

Compatibility interface
  Existing organization::combat_value retains its historical snapshot World
  callback contract. Its arithmetic shares health_ratio/add helpers with the
  borrowed loop. It was not silently changed into the new pointer/read service
  interface; existing native_org_tick tests are unchanged and still pass. New
  runtime bindings must use organization_combat_value::recompute for exact
  read/store/error order. No full dummy Organization or success-only copyback.

Evidence
  native_borrowed_combat_value.py executes unchanged original and v14 code,
  both functions, at PC24, PC53 and PC64. It pins full function ranges and the
  exact1 constant, as well as both PE and harness hashes. No arithmetic or call
  bodies are replaced. 306 cases =51 scenarios *2 images *3 precisions.
  20 scenarios stop at explicitly labelled required-service read/store cutpoints;
  these are synthetic dependency boundaries, not native exceptions or virtuals.
  Mutations at those boundaries test count growth/shrink, the initial count read,
  array swaps before/after recapture, changed second member/Performer/value, and
  accumulator rereads. These probes model mutable service implementations; they
  do not claim the unhooked native arithmetic spontaneously mutates its inputs.
  Two scenarios deliberately remove the second member or Performer. The native
  null-page guard verifies exact reads 5788F1:[74], 5788F4:[60], each4bytes. Rust
  returns Invalid and preserves identical earlier current/maximum stores instead
  of dereferencing null. These12 rows are actual guarded native fault prefixes.
  Clear-bit5 slots contain NaN value bytes which must never be read/evaluated.
  Other arithmetic is finite, with nonzero Body maximum, and includes signed0,
  near-rounding values and large/small finite values. Nonfinite reached numeric
  inputs/division by zero are explicit aa_numeric errors; no x87 nonfinite or
  floating exception parity is claimed by this port.

Validation
  CARGO_TARGET_DIR=target/s-borrowed-combat-value
  cargo test -p aa-combat --test native_borrowed_combat_value --test native_org_tick
    --release --locked --offline -j4
  New replay compares every service event, native memory store, final word and
  outcome across306 rows. Existing maintenance replay verifies186 older rows.
  See tests-final.log and clippy.log for final recorded results.

Provenance and preserved failures
  Existing organization.rs and lib.rs were backed up before edits in backups/.
  The first generator attempt failed while overlaying v14's larger mapped image.
  native-generation-first-failure.log is preserved. The harness now maps the
  additional PE image range before overlaying all v14 sections and allocating
  inputs; the complete fixture was regenerated by native execution, never edited.
  Independent instruction audit is in the adjacent saved-org-combat research
  folder, authored by restore_review; independent replay follows separately.
  Original game executables, saves, assets and release folders were not modified.
