# Same-owner FX Texture source binding

The full View compiler now borrows the actual ResourceManager and current Texture policy for FXC types 6 and 7. Paths use the current owning GameData source directory (4763C0). The compiler stores the real manager-issued Texture Handle before the type7 policy calls. Type7 then pushes the actual default PixelFormat, enables reading and disables rendering, in native order. Source-only/request APIs retain their explicit runtime guard.

One current format cell, initialized by native 9E75F0 → 8696E0, lives in the existing same-Application Source/Pixel owner. Default pixels and Texture format pushes read that cell. Each Texture keeps its existing render-format list/count. The grow operation initializes unused native capacity slots, preserves previous capacity contents and stores the count before the new nine-word record. No second Texture or mutable setting snapshot is made.

The full View arena is retained by the canonical DataFXSession as one Arc. Created/Existing events can select the original compiled head from that same arena; they do not repeat Texture Find or policy side effects. A sealed SourceGraphsRead aliases the sole DataState mutex and carries a Weak Application identity. Catalog borrows it only in runtime scopes. A failed/unfinished loader is not converted to an empty graph, a different Resource Application is rejected before preparation, and the read capability fails after Application destruction. Immutable source transfer excludes the runtime loan. Actor/component/Ability/Animation source preparation also receives the real Texture services, while its existing request-only runtime guards remain intact.

The original/v14 policy oracle executes 570 rows at all three precision controls (1,140 executions, 425 executed instruction pins). It covers capacity growth, low-byte arguments, signed request counts, current writable-child traversal, flag rereads and 54 stopped prefixes. Allocation/free, mutex and diagnostic operations are explicit transports. Loaded source reload/disable-reading children are stopped at their first required boundary; no decoder or exception-unwind claim is made. The concrete wrapper uses the same manager mutex over each resolved-entry leaf in the exclusive source-preparation domain; it does not reproduce Win32 mutex ABI or arbitrary reentrancy.

`python native_texture_settings.py` performs an immutable native replay. `build_exact_settings.py` compiles and replays the exact settings kernel/tests. `build_exact_events.py` compiles the exact current event-constructor slices and replays all 96 Created and 864 Existing native cases, plus a selected-prior-head regression. Neither script links the full runtime.

Current runtime production and all test targets typecheck (`check-tests06.log`). The new installed-source test is `fx_graph::texture::tests::actual_radar_graph_retains_same_resource_and_settings_before_any_request`, with AA_GAME_ROOT and include-ignored. Its execution is queued for the parent's next coherent warm runtime binary; typechecking is not execution. It checks a real objective radar Texture, same allocation and format-list mutation, DataState idempotence, same Graph Arc, foreign Application refusal and retired capability refusal. It uses an explicit false hardware-model predicate only for its source-preparation laboratory segment; it does not claim actual GPU capability or World initialization.

Open boundaries: loaded Texture reading-source reload/disable; in-use diagnostics when reached; positive subtype effect execution; non-View runtime graph consumption; natural complete battle/render acceptance. These remain explicit required operations. There is no readiness token or battle-completion claim from this source compiler.
