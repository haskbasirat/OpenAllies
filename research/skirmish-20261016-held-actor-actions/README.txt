Held Actor action rebuilding
============================

saved_actor_actions::rebuild(catalog, inventory, &mut Record, live_precision)
executes the existing native-backed4D1350 coordinator and its existing concrete
contributors over the actual saved Actor. It validates the canonical definition,
source Bank, immutable source precision, class/layout, component mask and current
held Loading generation before touching the action words. The current full Mind
must be back in its actual slot before entry. The existing Mind contributor then
moves, uses and restores that same owned core/state allocation on every Result.

SavedActions previously required an OrganizationAttachContext even when the
current actor was an ordinary Element. Its has_component implementation treated
every held owner as having Organization, and org() returned the mandatory detached
Organization. This forced an unrelated or fabricated Organization into callers
that only needed the actual Actor. The new shared SavedActionContext has an
optional borrowed detached Organization. Existing real attachment contexts
convert into Some; ordinary actors pass None and use their actual component
table. An Organization still in the actor's slot is found normally. No new
Organization, Actor, Mind, GTID table or command-mask cache is constructed.

The native4D1350 coordinator retains its exact clear/dispatch/publication order.
ActionF0/F4 and typed state bits are the actual mutable ActorShell storage. Native
positive Element readiness can set bit30 without Organization. A later required
owner-view or renderer service preserves the already completed action stores.
Missing unported contributors or services remain explicit reached errors.

Immutable source materialization is separate from live action arithmetic.
SavedActions::source_precision lazily uses the installed Bank State's precision
after checking its complete source-identity universe against the Catalog. Only
the existing no-State standalone diagnostic adapters keep their explicit source
precision input. New held-actor entry requires an actual source Bank. Layout,
Actor binding, ActorState resupply, Construction, Recruit/Research, MobileData,
Mind ability binding and authored settings reads use source precision; live Mind
and MobileDeployment arithmetic keep the caller's current check precision.
The economy adapters' corresponding change is owned and tested separately by
sdk_native_geometry_review, using the same source_precision getter.

Native proof
------------
native_held_actor_actions.py executes complete4D1350, native571640, ordinary
owner getter4D1E80 and native4CFCC0 in separate original/v14 machines at all
three precision modes. There are144 paired rows /288 executions,162 executed
instruction-address pins and two separately labelled stopped boundary-entry
pins. No body is answered with a synthetic successful result.76C7F0 and4CFD0E
are exact required boundaries; the tool stops before their instruction/body
effects. The fixture deliberately has no Organization or Mind pointer. Positive
Mind integration belongs to the separate current saved-Mind initialization test.
The existing native-actor-init-gates.json owner_virtual108 proof independently
pins both admitted class3/class4 native slotsA274F8/A29AE0 to4D1E80, whose body
reads the actual Actor+E8 word. The new fixture uses that same getter body.

The portable Rust test uses explicit synthetic field storage to check the shared
borrowed adapter against every native row, actor/component/state pointer identity,
and Loading ownership. It is not a source-completion certificate. A second test
proves the public entry refuses an unbound source before mutating the current
actor. Actual public-entry integration uses the first four original Kursk Mind
owners in load_mind_init_world's separate source-bound tests; that evidence must
be pinned at the current combined source revision before claiming it passed.

The old Organization action tests retain the same real detached allocations via
From<OrganizationAttachContext>; their literal conversions and Option access are
mechanical. No original game files, save, profile, native binary, release or
manifest is edited by this slice. It does not certify full Init/PostCreate,
registration, WorldStart, graphics, unwinding, positive UI services or a playable
battle.

Reproduce native fixture without changing it:
 PYTHONPATH=reconstruction/tools/python-packages python -B research/skirmish-20261016-held-actor-actions/native_held_actor_actions.py

The focused Rust module is saved_actor_actions::tests. Parent coordinated one
combined warm runtime-unit binary with the saved-Mind author rather than two
duplicate cold LTO builds. Test outcomes and final hashes are recorded separately.
