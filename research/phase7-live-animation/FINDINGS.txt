Live animation controller and per-actor GPU/picking bridge — Phase7

Production components
- aa-animation/controller_clock.rs ports native89E9B0 with incremental first/last/accumulated time, frequency changes, phase, repeat/reverse/clamp modes, f32 storage boundaries and the shared global-style result cache. Empty cache is an explicit initial condition.89E990 reset preserves the old accumulator until first evaluation zeroes it.883F50 relative sequence time is stored before controller evaluation;7170F0 writes negative Animator start and overwrites frequency. Application-time controller bit0 requires an external provider and rejects in this implementation. Precision is explicit.
- sample_controller_times supplies individual evaluated times to the existing NIF/KF interpolation/skinning engine; the old inspector sample API remains unchanged. NiKeyframeController8C0370 sets byte+30=0, so its8C0200 path evaluates scaled time once before interpolation; this avoids erroneously modeling the base-class double-query optimization.
- live_animation.rs binds the exact prepared source model to a manifest-hashed, source-verified original rig and the canonical runtime animation to its exact source KF, independent of clip labels. Original source NIF, converted topology/material mapping and KF byte hashes are checked. The current live rig manifest covers the initial five infantry rigs and four recovered clips per rig. Other original resources remain explicit errors, not generated substitutes.
- ActorRig.pose directly borrows the same authoritative CharacterState<String>; the clock is supplied by root. No authoritative state clone, private time progression, order generation or gameplay event execution occurs. The bridge retains its presentation controller state, stages all pose/picking changes, then updates the actor's exclusive GPU vertex buffers. Existing actor transforms/team colors/visibility, textures/materials, other model poses and renderer epoch remain intact. Animation key changes reset the selected presentation controller state; detailed native resource reactivation/blending is not claimed.
- GPU update_actor_vertices validates the entire slot set, rejects shared/multi-instance/terrain slots, and updates only the target actor. Transparent bounds switch to the same posed-AABB approximation already used by animated inspection. Picking replaces only exclusively owned local geometry and recomputes bounds; rejected GPU validation does not publish picking or controller time.
