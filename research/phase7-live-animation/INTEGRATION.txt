Original live actor pose integration

1. Build a source-resolved PreparedSpawn through the already reviewed live_scene::spawn::prepare API.
2. Before consuming it, let rig = prepared.prepare_rig(store,&settings,renderer.scene_epoch())?;
3. For the current canonical Character.animation key, resolve ActorStore.animations.get(key).source (BoundAnimation) and call rig.bind_clip(store,key,&source). The exact source KF path and original bytes are checked. Repeated keys reject instead of silently overwriting an existing definition.
4. Publish the original actor via live.append(renderer,objects,prepared).
5. Keep one ClockCache shared across live actors in their presentation traversal order. Obtain a direct borrowed &CharacterState<String> from the authoritative actor component box and provide actual client-time F32. Call rig.pose(&live,&mut renderer,&mut objects,character,client_time,&mut cache,precision).
6. World movement/visibility/team color use the existing live.apply API; instance matrices stay resident. Pose changes update only the exclusively owned actor mesh buffers and its picking BVH. Current source model/aspect, ID and epoch must still match.

The source bank chooses animation; this renderer never picks a clip from a label, defaults to Idle, advances a private animation clock, or runs gameplay FX/cues. Every requested canonical key must be bound; absent KF recovery or an unsupported relative expression is an explicit error. Current assets-cache/animation/manifest.json indexes the five original infantry rigs; the separate family manifest is not yet used by this live source resolver. The supported cached infantry rig subset currently includes Idle/Jog/Attack1/Die1. Native actor-side View/state changes requiring a different model/rig remain a separate publication operation.

Current strict scope: original serialized KF controller policy, native external-time clock89E9B0 and playback parameter44F8A1 composition, existing inspected interpolation/skinning. Do not claim native runtime loop overrides, KF acquisition/sequence initialization, blending, root-motion extraction, visibility/material controller or exact native interpolator parity. The available clock itself supports repeat/reverse/clamp/mode3 and rates changing over time, with executed native evidence; determining what policy the whole game's resource/sequence setup applies is separate. Finite active controllers only; application-clock bit0 and invalid/uninitialized time ranges reject. Float quantization at pause subtraction can produce last-bit pixel variation at nonbinary decimal times, matching the stored native arithmetic.
