ObjectData+16D required-object backreference byte
==============================================

Native49C760 clears this byte (49C970 store). Full49C460 verification sets it
to1 if an ActorData+4E0 required-object pointer equals the current ObjectData.
4BB110 obtains the type2 registration-list head; the native verifier traverses
node+8. This byte is not an authored announced boolean. The existing complete
NativeSourceRequirements receipt already excludes nonempty required_object_ids
and Upgrade graphs (including45FAE0 inheritance), and retains the exact source
universe/provenance. A narrow ObjectData-only byte(16D) getter can therefore
certify the constructor zero on that supported source domain. Nonempty writers
still refuse; this change does not implement their historical deferred callbacks.

The runtime Context borrows that actual immutable owner and the same Catalog
through with_source_fields. Source/PC/receipt checks occur at the reached16D
read: canonical held Source, its actual Bank source PC, all source identities,
canonical registration/provenance and native kind must agree. Visibility and
footprint additionally reject a foreign Catalog borrow. This adds no source
default to old Context::new / with_kingdoms callers without the new binding.

native_source_memory.py executes84 controlled cases and3 actual absence-census
cases in174 separate original/v14 machines/all3PC, with63 executed pins and no
body seams. Real ObjectData and ActorData virtual38 entries are used. The
constructor proof is ONLY the49C970..976 store with explicit ESI and BL=0,
not execution of the full heap/TLS constructor. The complete49C460 body and
4BB110 execute with explicit empty unrelated verification lists. Positive,
unrelated, duplicate and pre-set-byte controls verify the actual backreference
operation; those controls do not extend the Rust supported domain.

The actual inputs are the separately frozen source-requirement census:1084
standard/derived ActorData definitions, including56 RandomActor entries, at
each source PC. Every4E0 is null. The fixture feeds this complete conservative
set through the native iterator. It does not claim to have recovered native
type2 list membership/registration ordinals/order. The all-null conclusion
holds for any eligible subset/order; native actual object-pointer values are
not needed to establish absence. Existing source-producer evidence remains at
skirmish-20261016-live-placement/source-requirements.

The new actual rules test rebuilds the complete1959-definition receipt from
original/v14 assets at all3PC, checks every supported ObjectData16D getter
against the independent native result, and rejects non-ObjectData reads. It
exports only to a new research output when AA_SOURCE_MEMORY_CAPTURE is supplied.
Full aa-rules/aa-metagame required checks run with AA_METAGAME_EXPORT=0.
