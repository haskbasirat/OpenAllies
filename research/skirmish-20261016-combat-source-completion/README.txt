Delivered
---------
aa-runtime::combat_source_completion owns the CV dependency slice of native
4BD800: 4BBF90 produces the eight manager means, then 4BB590 walks native-kind-2
ActorData roots in reverse registration order and recursively calls 4618B0.
It uses actual AA source fields and the existing instruction-proved combat
kernels, including native 45E090 and the proven SSE2 CRT pow algorithm. The
1028 cache triples are computed, never copied from the reference capture.

One non-Clone State belongs to the existing canonical definition Bank. Its
ActorDefinition/ActorLocalAbility/AbilityDefinition/Property tokens are the
same Bank identities used by the runtime. Constructor cache values are
1E4=BF800000, 30C=0, 36C=0; no constructor marker certifies completion. Mean and
value phases mutate this one owner progressively, retain partial writes on
failure, and cannot be retried or replaced. Binding can intern tokens before
a later binding error; it is deliberately NOT advertised as transactional.
State installation itself occurs only after the whole input graph binds.

Numeric inputs retain all ten actual typed settings and their declaration
provenance. CSV inputs retain the whole actual root-UVars source set. FP/CRT
context is explicit and separate from restore precision. A diagnostic context
can compute evidence but cannot publish completed native-startup values.
Completed getters require a sealed verified captured-reference context and a
computed fingerprint of all 1028 triples, native IDs/order, reached component
bits, and all eight means. The fingerprint is checked only after computation.

VerifiedStartupReceipt::verify_embedded_reference checks compiled fixed
capture03/manifest seals, current logical definition source identities, ten
typed setting values, and complete root UVars before attaching the sealed
reference capability. It requires no native EXE/DLL/config at runtime and
executes no native code. This describes the verified isolated fresh-profile
v14/dgVoodoo reference target, NOT observation of the current Rust process.
The external verify(TargetFiles) API additionally hashes the actual reference
EXE, D3D9.dll and dgVoodoo.conf for reproducible research audits. Both paths
still require the Rust source computation and whole-result fingerprint before
completed getters succeed. Changing arbitrary JSON, labels, a profile scope,
or reference build bytes cannot mint this capability.

Prior source passes and boundaries
---------------------------------
This is CV-only source completion, NOT a complete 4BD800/source-loader or
world-start/gameplay certificate. The shipped registered graph has zero
Upgrade instances and zero category21 Settlement definitions; its Settlement
component and WallSet counts are also zero. Thus 4BB480/4BB130 have no shipped
reached upgrade/Settlement work. 4BB730 weighted placement-group completion is
CV-disjoint on the typed nonalias graph. The independent review/ directory
contains 54 original/v14/all-PC prerequisite write-set probes plus all24 native
constructor/vtable+30 checks. These do not certify omitted non-CV phases as
completed. Actor/ObjectData shape+64 and AbilityDefinition power+64 are distinct
owners; equal offsets are not evidence of aliasing.

Supported completion inputs are the current shipped kind2 transitive graph,
with no shared Performer definition alias, Faction overwrite of an embedded
Performer definition, Settlement extent, Upgrade graph, preexisting source
lazy caches, open/nonempty CSV stream, or unmasked x87 exception semantics.
Those other corpora refuse explicitly. Finite-domain and allocator/SEH limits
of the existing kernels remain. No artificial RAM/VRAM/bandwidth cap or new
balance/default behavior was added. Full gameplay, AI, commands, networking,
world placement, and later source phases are not proved by this receipt.
