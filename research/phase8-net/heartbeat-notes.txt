1. NATIVE STRUCTURE (all [ORACLE] unless marked)
------------------------------------------------
Peer list AdminNode+0x2AC holds the node itself and its AdminConns; vtable
+4 is "as conn" (node 0x4C9FA0 -> 0, conn 0x8D6180 -> this).
"Server" = AdminNode+0x2C8 == node, "host" = +0x2C4 == node.

0x75B820 heartbeat (frame update 0x75CA70 calls it when NetNode+0x58 >
AdminNode+0x2DC, next = 1.0/AVar 0x47 + now; scheduling is in aa-runtime):
  server: for every peer 0x7593E0 (backup requests, 1 bit type: 0 chat
    0x753940, 1 vote 0x74F890), then 0x75A2C0 DisconnectLostPlayers;
  server and DAT_00B40934 >= 16 (signed): 0x74F1A0 + 0x752C60, counter = 0;
    else counter += 1 (also on clients) -> refresh on every 17th server tick;
  0x75A0C0 ProcessBackupDecrees (2-bit type: 0 status, applied only when not
    server; 1 chat -> "public_chat|ss"; 2 ignored; 3 = 0x411FA0 assertion,
    a Rust error);
  host: 0x74F310 for every conn (status 2 only; 1 when bytes == size;
    request 305 {player conn+8, 2-bit status, binary32 sent/size}).

Backup request packets (client -> server, peer+0x1C history):
  chat 0x74F950: 1 bit 0, 16-bit count, count*16 bits (count = low 16 bits
  of the CString length); vote 0x74C3D0: 1 bit 1, 1 bit vote. Senders
  0x753410 / 0x7532D0 append to the own +0x1C history, keep end-1000.
Backup decree packets (server -> all, node+0x224, keep end-200):
  chat 0x74FA20: 2 bits 1, CString, 32-bit player id (0 = null);
  status 0x74E530: 2 bits 0, 32 votes (+0x2B8), 32 max patience bits
  (+0x2BC), per peer 0x74C450: 1 +0x48, 1 +0x49, 1 +0x4A, 1 +0x4B, 32 +0x4C,
  32 +0x50, 1 +0x30, 1 +0x55, 32 +0x60 (reader 0x74C590 stores ==1 bytes).
  A client reads one record per entry of ITS list (no count on the wire).

0x74F1A0 lag refresh: votes and max patience (0x74DD80, lagging conns,
from 0.0, NaN ignored) are taken BEFORE the slots run; per peer slots
+8..+0x20: node 0x5AA2D0 (+0x4C=0), 0x74B270 (+0x50=0), 0x74B2A0 (+0x4B=0),
0x74B2B0 (+0x49 = NetNode+0x64 byte), 0x74B2D0 (+0x4A=0), 0x74B2F0 (+0x30 =
+0x31 byte), 0x74B300 (+0x48=0); conn 0x74B260 (+0x4C = NetConn+0x38 bits),
0x74B280 (+0x50 = 0x7642D0 received fraction), 0x74D490 (+0x4B: not
connected -> 0; else (node+0x228 - 0x7626A0(+0x2AC)) > AVar 0x4F or +0xA8,
host also (node+0x218 - 0x7626A0(+0xCC)) > AVar 0x4B), 0x74B2C0 (+0x49 =

2. x87 (explicit precision; PC53 is the network thread's mode)
--------------------------------------------------------------
Precision independent (one operation on binary32 operands, binary32 store;
double rounding innocuous for 53 and 64 >= 2*24+2): dt, patience decrease,
UpdateFileTransferStatus fraction, SetHost period.
Precision dependent, all exact in Rust for PC24/PC53/PC64:
  * patience increase (two roundings). PC24 != PC53 proven by 8 targeted
    cases (3 found by exact search, 5 constructed: dt = 80q*2^-24, q odd).
    PC53 != PC64 would need the exact sum within 2^-53 (relative) of a
    binary32 midpoint without being on it. With 0.1f = (2^26+1)/(5*2^27)
    the product is never within 0.025 grid units of a midpoint (numpy scans
    of dt significands in [2^16,2^17), [2^20,2^21), [2^23,2^24)) and no
    usable 29-bit bit run exists in dt*0xCCCCCD for any significand below
    2^24 (exhaustive scan), so no input was found; the
    Rust PC64 branch is exact by construction but not oracle-distinguished.
  * in-register comparisons (now - t) > 2.0 / 3.0: PC24 != PC53 cases
    (t = 2^-22 - 2^-30) and PC53 != PC64 cases (t = -2^-60) are in the
    fixture for the disconnect reset and both liveness limits.
  * received fraction fild/fidiv: exact rational rounding (24, 53->24,
    64->24); 15 cases with windows up to 2^25+7 entries (counts above 2^24,
    where int->float conversion would already be inexact).
NaN: x87 propagation rules are implemented (SDM table 4-7, default NaN
0xFFC00000) but there are no NaN fixtures (Unicorn does not quiet SNaN
loads): unproven.
