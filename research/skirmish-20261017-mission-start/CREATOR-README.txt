Creator/resource launch binding: bounded implementation and proof

The new resource_creator owner distinguishes five native values: fresh selected
CreatorLoad, source MapResource+88, source Header+90, mutable Session+68
GameSettings (peer-owned), and target MapResource+88. Mutable vectors and current
label/modified-byte companions are copied into independent allocations. Only the
immutable SourceResource Arc and canonical source metadata are shared. The +50
source link, actual resource IDS and weak archive witness remain distinct from
header display labels and hashes. Load+50=NULL is a valid constructor state;
5A2D09 dereference requires the actual selected source later.

The real selected path prepares constructor clone/header before the World sink,
then checks the same selected Creator witness and performs final5A2FCF selection
after the GWorld constructor but before4FC600 mission words, RULES and TERRAIN.
World::before_first_record_prepared consumes the same stable mode Box and resource
companion. Root's load_selected_owned_runtime consumes the already completed
Catalog/Bank instead of creating another source arena. The older unselected
record loader remains diagnostic and cannot validate a completed Creator.

Fresh CreatorLoad5141F0 calls the recovered parameter/rules constructors. Current
UVars192/192 and SVars DefaultKingdomsIndependent0/default Biome are retained by
creator_variables under explicit ControlledNone override scope. Unknown overrides
are refused. Native510DC0 creates TWO major Kingdom parameters, plus any actual
independent count; it does not construct an empty array. Source +0C omissions
retain native initialized empty strings, and Resource arrays use the actual
native resource registry order, zero-fill, then known saved overwrites. Unknown
Resource warning paths remain required. WorldRules constructor chooses the FIRST
actual GameType manager entry. The registered source defaults and descriptors
are validated against the same completed source FP owner/startup receipt.

CreatorRules are separate from the sole mutable standalone GWorld Rules owner.
Actual4FC804..857 first loads standalone RULES, then copies current Creator
mode/GameType/vector/change-counter when resource+A8 bit1 is clear; mode2 instead
resets editable records. Only afterward are those current Rules published to the
same retained SVar owner. Current bool511AF0 uses first case-insensitive IDS,
without Translate: absent or wrong-type is a no-op; a valid raw-byte store
preserves upper24 bits and increments the wrapping counter even if unchanged.

creator_labels and game_settings_value have their own separately owned proofs.
Actual5144A0 copies the source owner's CURRENT localized pair companions; it does
not retranslate keys using a later table. Missing nonempty-key fallback remains
unbound until a genuine writer supplies it. Raw modified68 bytes live beside the
same parameters, are constructor/source initialized0, and copy independently.

The focused current Rust actual-data test covers tutorial02, Firefight and Berlin
with one sealed source Bank: constructor values, current GameSettings copying,
