SCHEDULE AND MEASURABLE EXIT CRITERIA
There is no reliable overall completion percentage or finish date. Treat a
multi-month full faithful rewrite only as a planning assessment, potentially
longer, not a measured estimate, commitment or countdown. Current function/test
counts cover bounded inputs and explicit required seams; they cannot establish
how many dependent behaviors remain or certify end-to-end gameplay.

1. First real initialized world: one original map completes immediate object
   lifecycle, conversion drain, later PostLoad, actual lists/managers, mission
   initialization and publication with no fabricated callback. Expand native
   state/list/queue/RNG comparisons and map/save-version coverage afterward.
2. First ordered simulation: that world performs actual native-order admin,
   decree and component updates through required services over multiple ticks,
   retaining the single authoritative clock and RNG. A test clock alone fails
   this gate. This provides a more useful basis for estimating first skirmish.
3. First complete skirmish: original unit commands, movement/pathfinding,
   combat/death, building/recruitment/economy, fog/AI, victory/defeat and save/
   reload/restart operate together. This remains the user's first priority.
4. Multiplayer: deterministic two-process skirmish, then real lobby/hosting/
   joining, decree history, synchronization/recovery and save-transfer tests
   across separate PCs and connections. Required separate-internet equipment
   was unavailable in the last human answer; do not claim that acceptance.
5. Campaign/WWII: original scripted missions, objectives, transitions,
   progression, metagame and save compatibility follow those foundations.

The final target remains the original game's behavior in an x64 Windows EXE,
original assets/maps/units/nations/animations/audio/UI, skirmish, multiplayer,
campaign/WWII and compatible saves where actually verified. Recoverable source,
research, tests and packaging should make continuation possible. Engine memory
