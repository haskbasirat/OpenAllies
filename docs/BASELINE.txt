Native-only preservation evidence
The ledger pins accepted source proposals for zoom, repaired WASD, text-reset
dependency rebuilding, Original-only retirement, fullscreen, DPI, LAN discovery
and OpenSpy. Earlier file-transfer/history fixes and profile isolation remain
inside the exact accepted native image. A Rust implementation must recreate
the intended behavior safely; it must not copy native pointer bugs, blindly
transpile decompiler output, or label a recreated menu as full behavioral parity.

dgVoodoo.conf changes only VRAM256 ->2048 from v13. D3D9 is translated to D3D11
FL11.0 in that old native package. These are renderer implementation settings,
not combat/economy rules. A new64-bit Rust renderer may use modern GPU APIs;
matching original artwork, layouts, effects and gameplay still needs validation.
LAA/up-to4GiB old-process address-space allowance is not a gameplay mechanic.

Loading policy for a future Rust rules catalog
1. Read verified original archive members.
2. Replace matching file bytes with the exact declared v14 loose Data files and
   add the five declared new files, respecting native resource paths/stages.
3. Parse inherited templates and native ordering. Do not merge independently
   named fields as a substitute for whole-file replacement or native inheritance.
4. Apply independently ported native behavior (zoom/input/transport/UI lifecycle)
   using its own evidence/tests; the Data overlay does not implement it.
5. Keep user preferences and saves separate; do not import credentials or claim
   native RSG compatibility before that decoder/state graph is actually ported.

Current aa-assets loads original terrain/placements/static converted models and
textures, not gameplay resource/unit/nation/economy rules. That viewer path does
not itself reset the rule baseline, but a future rule loader must use this ledger.
Current aa-simulation exposes an explicit provider maximum; v14 callers must
eventually supply100. Its tests include20 and100 because native arithmetic is
tested independently of profile selection. The default16Hz evidence is shared.

Current implementation remains a foundation. See PARITY.txt for missing native
systems. There is no claim that the complete v14 game has already been rebuilt.
